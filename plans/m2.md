# M2 — io_uring, TCP, scope, deadline, hủy

Vẫn một worker (nhiều worker là M3). Mục tiêu: fiber gọi I/O trông blocking, hủy và
deadline đúng tuyệt đối — không có đường nào để kernel ghi vào stack đã bị bỏ.

## Bất biến (mọi thứ khác phục vụ mấy dòng này)

- **I1** Một `em_op` nằm trên stack fiber; nó được nộp → fiber chỉ chạy tiếp sau khi
  **CQE của chính op đó** về. Không có ngoại lệ: hủy, deadline, đóng fd, deadlock đều đi
  qua CQE.
- **I2** Fiber đang chờ op ở state `EM_IOWAIT`. `em_unpark` bỏ qua state này — người dùng
  không thể đánh thức nhầm fiber đang chờ kernel.
- **I3** Mỗi op đúng một CQE (không multishot, không send_zc ở M2). SQE phụ (link timeout,
  async cancel) mang `user_data = 0` và CQE của chúng bị bỏ qua.
- **I4** Mọi fiber thuộc về đúng một scope. Không có spawn tách rời.
- **I5** Chỉ nộp `ASYNC_CANCEL` cho fiber đang ở `EM_IOWAIT`. Mọi SQE đã chuẩn bị đều được
  submit trước lần gặt CQE kế tiếp → một cancel không thể trúng op *mới* của fiber nằm ở
  cùng địa chỉ stack (fiber chỉ chạy lại sau khi gặt).

## Thư viện

Dùng **liburing** (2.13 có sẵn, header-heavy, chuẩn de-facto) thay vì tự viết ring ~300
dòng. Link động `-luring` ở M2; M4 vendor source để crate Rust build không cần
liburing-devel. Container arm64 cần thêm `liburing-devel` → sửa
`tools/arm64.Containerfile` và build lại image.

## Ring và vòng lặp worker

- `io_uring_queue_init_params(4096, SINGLE_ISSUER | DEFER_TASKRUN | SUBMIT_ALL, cq = 2×)`.
- Khởi động thất bại → `em_run` trả lỗi phân biệt được, không fallback:
  `-EPERM` (sysctl `kernel.io_uring_disabled` hoặc seccomp), `-ENOSYS` (seccomp/kernel
  không có io_uring), `-EINVAL` (kernel < 6.1 không hiểu cờ). Ghi rõ trong `em.h`.
- Vòng lặp:
  ```
  loop:
    chạy hết run queue
    if live == 0: break
    if inflight == 0: deadlock (xem dưới)
    io_uring_submit_and_wait(1)
    for cqe: if user_data: op->res = res; inflight--; op->fiber → READY
  ```
- `io_uring_get_sqe` trả NULL (SQ đầy) → `io_uring_submit` rồi lấy lại.

## Op

```c
struct em_op { em_fiber *f; int32_t res; uint8_t uncancellable; };   // trên stack fiber
```
`op_submit_wait(sqe)`: kiểm tra hủy trước (đã hủy → trả `-ECANCELED`, không nộp);
gắn deadline nếu có (dưới); `user_data = &op`; `f->cur_op = &op`; inflight++; park ở
`EM_IOWAIT`; về → `cur_op = NULL`; dịch kết quả (dưới).

## Scope (structured concurrency, Trio/errgroup)

```c
typedef struct em_scope em_scope;   // nằm trên stack của fiber mở nó
void em_scope_open(em_scope *s, int64_t deadline_ns);  // 0 = không deadline; absolute CLOCK_MONOTONIC
int  em_spawn(em_scope *s, int (*fn)(void *), void *arg);
void em_scope_cancel(em_scope *s);
int  em_scope_close(em_scope *s);   // chờ hết con; trả lỗi đầu tiên (con hoặc -ETIMEDOUT/-ECANCELED), 0 nếu sạch
```
- **Đổi API M1**: hàm fiber trả `int`; `em_spawn` nhận scope; `em_run(main_fn, arg)` chạy
  main trong scope gốc và trả giá trị của scope đó. Sửa 6 test M1 theo.
- Dữ liệu: scope có `parent`, `deadline` (= min với parent khi mở), `cancelled`,
  `first_err`, danh sách con intrusive hai chiều (`em_fiber.sib_prev/sib_next`, `scope`),
  `nchildren`, `closer` (fiber đang chờ close).
  Fiber có `cur_scope` (scope trong cùng nó đang mở, hoặc scope nó được spawn vào).
- **Fail-fast**: con trả khác 0 → ghi `first_err` (nếu chưa có), cancel scope.
- **Đã hủy?** = đi ngược chuỗi `cur_scope → parent` tìm `cancelled`. O(độ sâu), rẻ.
- **Cancel(S)**: `S.cancelled = 1`, rồi ngắt mọi fiber nằm dưới S (DFS: con của S, và
  scope lồng do con mở): fiber đang `IOWAIT` với op hủy được → nộp `ASYNC_CANCEL` nhắm `cur_op` (vẫn chờ
  CQE gốc, I1); fiber `PARKED` bởi `em_park` → READY, `em_park` trả `-ECANCELED`; fiber
  đang chờ close → không làm gì (con của nó tự bị ngắt).
- `em_scope_close` phải gọi theo thứ tự LIFO trên chính fiber đã mở (assert).
- Fiber kết thúc → gỡ khỏi scope, `nchildren--`, về 0 và có closer → unpark closer.

## Deadline

Không có timer wheel. Op nộp trong scope có deadline → SQE đi kèm `IOSQE_IO_LINK` +
`io_uring_prep_link_timeout(ts, IORING_TIMEOUT_ABS)`; `ts` nằm trên stack fiber (sống
tới CQE). Kết quả `-ECANCELED` mà chuỗi scope không bị hủy → trả `-ETIMEDOUT`.
Deadline đã qua lúc nộp → trả `-ETIMEDOUT` ngay, không nộp.

## Deadlock (trả nợ M1)

Run queue rỗng, `inflight == 0`, còn fiber sống → cancel scope gốc. Các fiber `PARKED`
tỉnh dậy với `-ECANCELED` và tự unwind (Rust sẽ chạy được `Drop`). Nếu sau đó vẫn kẹt
(không ai tiến được) → munmap mọi stack (danh sách scope cho biết hết fiber).
Đã phát hiện deadlock thì `em_run` luôn trả `-EDEADLK`, kể cả khi unwind sạch. Xóa comment DEBT trong `em_run`.

## API I/O

```c
int64_t em_now(void);                                  // CLOCK_MONOTONIC ns (vDSO)
int  em_sleep_until(int64_t deadline_ns);              // OP_TIMEOUT abs; 0 / -ECANCELED / -ETIMEDOUT
int  em_tcp_listen(const struct sockaddr *a, socklen_t n, int backlog);  // syscall thường, SO_REUSEADDR; fd / -errno
int  em_accept(int lfd);                               // OP_ACCEPT, SOCK_CLOEXEC; fd / -errno
int  em_connect(const struct sockaddr *a, socklen_t n);// socket() + OP_CONNECT; fd / -errno
ssize_t em_recv(int fd, void *buf, size_t len);        // OP_RECV; 0 = EOF
ssize_t em_send(int fd, const void *buf, size_t len);  // OP_SEND, MSG_NOSIGNAL; có thể gửi thiếu
int  em_send_all(int fd, const void *buf, size_t len); // lặp tới hết; 0 / -errno
int  em_shutdown(int fd, int how);                     // OP_SHUTDOWN
int  em_close(int fd);   // ASYNC_CANCEL(FD|ALL) chờ xong, rồi OP_CLOSE — fiber khác đang recv fd này tỉnh với -ECANCELED
```
`em_close` không bị hủy được (luôn đóng fd, kể cả trong scope đã hủy) — không thì leak fd.

## Test — xong M2 khi xanh ở x86_64 `-O2`, x86_64 ASan, aarch64 `-O2`

1. **echo**: 1000 kết nối loopback, mỗi cái 1 MiB dữ liệu giả ngẫu nhiên, so khớp từng byte.
2. **deadline**: recv trên kết nối im lặng trong scope deadline 50 ms → `-ETIMEDOUT`,
   thời gian thực trong [50, 150) ms.
3. **đua hủy**: 10k vòng — fiber A recv, fiber B gửi dữ liệu và cancel scope ở điểm
   ngẫu nhiên (số yield ngẫu nhiên, seed in ra). A nhận được dữ liệu *hoặc* `-ECANCELED`,
   không gì khác; `inflight == 0` cuối mỗi vòng; ASan sạch.
4. **fail-fast**: một con trả `-EIO`, anh em đang `accept`/`recv` nhận `-ECANCELED`,
   `close` trả `-EIO`.
5. **lồng**: cancel scope ngoài → cháu đang recv trong scope lồng tỉnh dậy.
6. **close khi đang recv**: fiber B `em_close(fd)` lúc A recv fd đó → A `-ECANCELED`, không treo.
7. **sleep**: 1000 fiber ngủ tới các deadline xáo trộn, thức dậy đúng thứ tự deadline.
8. **io_uring bị chặn**: process con cài seccomp filter trả `EPERM` cho `io_uring_setup`
   → `em_run` trả `-EPERM`.
9. **deadlock**: fiber `em_park` không ai unpark → nó nhận `-ECANCELED` và thoát; `em_run`
   trả `-EDEADLK`; không còn mapping nào (đếm mmap = munmap).
10. Sáu test M1, sửa theo API mới, vẫn xanh.

## KHÔNG làm ở M2

- Nhiều worker, `SO_REUSEPORT`, `MSG_RING`, UDP → M3.
- Multishot accept/recv, provided buffer ring, fixed files, SQPOLL, send_zc → chỉ khi M5 đo ra cần.
- Timeout theo từng lời gọi (tham số timeout trên recv/send): deadline đi theo scope,
  một cơ chế duy nhất. Cần timeout riêng cho một lời gọi = mở scope con.
- Spawn tách rời (không scope), join theo handle.
- DNS, offload pool, TLS, Rust binding.
- Không tự viết ring thay liburing.

## Trade-off ghi nhận

- Hủy là cooperative: fiber chạy vòng CPU không gọi op/yield thì không bị ngắt.
  Xét lại: không — preemption mâu thuẫn D2.
- Mỗi op trong scope có deadline tốn thêm 1 SQE (link timeout). Xét lại khi M5 đo SQ là nút thắt.
- `em_close` đồng bộ hóa hủy + close: 2 vòng kernel. Xét lại khi fixed files vào (M5).
