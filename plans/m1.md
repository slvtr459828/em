# M1 — fiber + scheduler một worker

Mục tiêu: một thread chạy được hàng nghìn fiber stackful, chuyển ngữ cảnh rẻ, an toàn bộ nhớ.
Chưa có I/O. M2 sẽ dùng `em_park`/`em_unpark` làm điểm chờ cho CQE.

## Cấu trúc

```
include/em.h          API công khai (C)
src/internal.h        struct nội bộ
src/ctx_x86_64.S      context switch
src/ctx_aarch64.S     context switch
tools/arm64.Containerfile  image `em-arm64` (đã build sẵn: gcc + make, Fedora 44 arm64)
src/fiber.c           stack, fiber, run queue, worker loop
tests/*.c             test, mỗi file một binary
Makefile              build release / asan, `make test`
```

## Dữ liệu

**Một fiber = một mmap.** `em_fiber` nằm ở đỉnh vùng stack của chính nó:

```
thấp ─► [guard 4K PROT_NONE][........ stack 256K ........][em_fiber] ◄─ cao
                                              ▲ sp ban đầu, 16-byte aligned
```

Không malloc cho fiber. Thu hồi = đẩy cả mapping vào free-list của worker (intrusive,
dùng chính `em_fiber.next`), tái dùng không cần mmap lại.

```c
struct em_fiber {
    void        *sp;          // sp đã lưu khi fiber không chạy
    em_fiber    *next;        // run queue HOẶC free-list (không bao giờ cùng lúc)
    void       (*fn)(void *);
    void        *arg;
    uint8_t      state;       // READY, RUNNING, PARKED, DONE
    // asan: fake stack ptr, bottom, size
};
struct em_worker {             // __thread, một cái mỗi thread
    void        *sched_sp;    // ngữ cảnh của vòng lặp scheduler (stack gốc của thread)
    em_fiber    *current;
    em_fiber    *rq_head, *rq_tail;   // FIFO
    em_fiber    *free;
    size_t       live;        // fiber chưa DONE
};
```

## Context switch (x86_64 SysV)

`em_ctx_switch(void **save_sp, void *load_sp)`: push rbp, rbx, r12–r15 + MXCSR + x87 CW
(hai cái này callee-saved theo ABI), lưu rsp vào `*save_sp`, nạp `load_sp`, pop, ret.
Stack mới được dựng sẵn để `ret` lần đầu nhảy vào trampoline (bắt đầu bằng `endbr64`
cho IBT). Trampoline gọi `fn(arg)`, đặt DONE, switch về scheduler — không bao giờ return.

aarch64 (AAPCS64): lưu x19–x28, x29, x30, d8–d15, FPCR; sp lưu/nạp qua thanh ghi tạm.

Fiber luôn switch về scheduler, không switch trực tiếp fiber→fiber. Một kiểu chuyển duy
nhất, dễ lý luận; chi phí thêm một lần switch, đo ở test 1.

## API

```c
int   em_run(void (*main_fn)(void *), void *arg);  // chạy tới khi live == 0
int   em_spawn(void (*fn)(void *), void *arg);    // 0 / -ENOMEM; fiber vào cuối run queue
void  em_yield(void);                             // về cuối run queue
em_fiber *em_self(void);
void  em_park(void);                              // treo, không vào run queue
void  em_unpark(em_fiber *f);                     // PARKED → READY; gọi từ cùng worker
```

`em_spawn` không trả handle: join/hủy là việc của scope ở M2. Trả handle bây giờ = API
phải sửa lại sau.

Vòng scheduler: pop rq → switch vào → khi quay lại, nếu DONE thì đẩy vào free-list.
Run queue rỗng mà còn fiber PARKED → ở M1 là deadlock, `em_run` trả `-EDEADLK`
(M2: lúc đó mới chờ CQE).

## ASan

Gọi `__sanitizer_start_switch_fiber` / `__sanitizer_finish_switch_fiber` quanh mỗi
switch (bọc `#ifdef __SANITIZE_ADDRESS__`). Thiếu nó ASan báo lỗi giả và bỏ sót lỗi thật.

## Test — xong M1 khi tất cả xanh ở: x86_64 `-O2`, x86_64 ASan, aarch64 `-O2`

`make test` (x86_64 -O2), `make test-asan`, `make test-arm64` = chạy `make test` trong
`podman run --rm --arch arm64 -v $PWD:/src:Z em-arm64`. ASan không chạy dưới qemu-user.
Số ns/switch trên aarch64 là số của qemu, không có ý nghĩa hiệu năng — chỉ kiểm đúng/sai.

1. **ping-pong**: 2 fiber yield qua lại 10M lần; in ns/switch.
2. **churn**: spawn→exit 1M fiber tuần tự; số mmap thực hiện ≤ số fiber sống đồng thời tối đa.
3. **nhiều fiber**: 100k fiber cùng park, rồi unpark hết, tất cả chạy xong; FIFO đúng thứ tự.
4. **guard page**: fiber đệ quy vô hạn → process con chết bằng SIGSEGV (fork + waitpid),
   không ghi đè fiber khác.
5. **FP state**: fiber A đổi rounding mode (`fesetround`), fiber B không bị ảnh hưởng.
6. **deadlock**: tất cả fiber park, không ai unpark → `em_run` trả `-EDEADLK`.

## KHÔNG làm ở M1

- Nhiều worker, ghim core, io_uring, scope, hủy — M2/M3.
- Switch trực tiếp fiber→fiber, `madvise` trả RAM của stack trong free-list, kích thước
  stack tùy chỉnh theo fiber — chỉ làm khi số đo cần.
- Rust binding — M4.
- Không dùng thư viện coroutine ngoài (minicoro, boost.context): asm ~40 dòng, phụ thuộc
  ngoài đắt hơn.

## Trade-off ghi nhận

- **VMA**: mỗi fiber sống tốn 2 VMA (guard + stack). `vm.max_map_count` mặc định 65530
  (Debian/Ubuntu) → trần ~32k fiber; Fedora 1048576. `em_run` đọc giá trị này lúc khởi
  động để tính trần, và `em_spawn` trả `-ENOMEM` rõ ràng khi chạm. Xét lại khi cần
  >500k connection trên host không được chỉnh sysctl.
- **RAM stack tái dùng**: trang đã chạm của stack trong free-list vẫn chiếm RAM. Xét lại
  khi đo thấy RSS cao sau đỉnh tải.
- **CET shadow stack**: file asm không đánh dấu SHSTK → glibc tắt shadow stack cho cả
  process nếu nó bật. Xét lại khi cần chạy với user-space shadow stack bắt buộc.
