# M4 — crate Rust `em` (D4)

## Cổng chặn

1. **Không làm thì hỏng ở đâu?** D4 chốt Rust là binding đầu tiên và phạm vi v0 có crate `em`.
   Không có crate thì người dùng Rust phải tự viết FFI vào một API mà hỏng quy tắc là UB
   (fd dùng chéo worker, scope đóng sai thứ tự, panic chạy qua frame C).
2. **Chỗ nào đã làm gần giống?** API C trong `include/em.h`. Crate chỉ bọc nó, không thêm
   cơ chế mới ở runtime. `bench/rust/` đã có workspace Cargo để đặt server echo bản Rust.
3. **Phiên bản nhỏ nhất:** một crate, gói đúng API v0 (run, scope, spawn, sleep, TCP, UDP,
   read fd) thành kiểu Rust an toàn, `TcpStream: Read + Write`. Không async, không trait
   trừu tượng, không thêm primitive đồng bộ.

## Hình dạng API

```rust
fn main() -> std::io::Result<()> {
    em::run(0, || {                                   // chạy trên MỌI worker, như em_run
        let l = em::TcpListener::bind("0.0.0.0:8080".parse().unwrap())?;
        em::scope(|s| loop {
            let mut c = l.accept()?;
            s.spawn(move || {
                let mut buf = [0u8; 4096];
                loop {
                    let n = c.read(&mut buf)?;        // std::io::Read, trông blocking
                    if n == 0 { return Ok(()); }
                    c.write_all(&buf[..n])?;
                }
            })?;
        })
    })
}
```

| Rust | C | Ghi chú |
|---|---|---|
| `run(n, F) -> io::Result<()>`, `F: Fn() -> io::Result<()> + Sync` | `em_run` | `F` chạy trên mọi worker cùng lúc nên cần `Sync`. Panic trong `F` được bắt, `run` trả về xong thì ném lại |
| `scope(f)`, `scope_timeout(dur, f)` | `em_scope_open/close` | Mô phỏng `std::thread::scope`: fiber con được mượn biến của hàm gọi |
| `Scope::spawn(F) -> io::Result<()>`, `F: FnOnce() -> io::Result<()> + 's` | `em_spawn` | **Không** đòi `Send` (D2). `-ENOMEM` thì trả `Err` |
| `sleep(Duration)`, `yield_now()` | `em_sleep_until`, `em_yield` | |
| `cancel_all()`, `worker_id()`, `worker_count()`, `backend()` | cùng tên | |
| `TcpListener::bind(SocketAddr)`, `accept()` | `em_tcp_listen`, `em_accept` | backlog cố định 1024. Chỉ `SocketAddr`, không `ToSocketAddrs` (cái đó gọi DNS blocking; DNS là v0.1) |
| `TcpStream::connect(SocketAddr)`, `shutdown(Shutdown)` | `em_connect`, `em_shutdown` | |
| `impl Read + Write for TcpStream` **và** `for &TcpStream` | `em_recv`, `em_send`, `em_send_all` | `&TcpStream` để một fiber đọc, một fiber ghi cùng socket (giống std). `write_all` override bằng `em_send_all`, `flush` không làm gì |
| `UdpSocket::bind`, `recv_from`, `send_to` | `em_udp_bind`, `em_recvfrom`, `em_sendto` | |
| `read_fd(BorrowedFd, &mut [u8])` | `em_read` | Cho signalfd/eventfd/pipe, ví dụ để tắt server êm khi nhận SIGTERM |
| `Drop` của socket | `em_close` | |
| `AsFd`, `AsRawFd` | | Để set sockopt bằng `socket2::SockRef` mà không phải bọc thêm |

## Ngữ nghĩa — chỗ khó và cách xử lý

1. **D2 được ép lúc compile.** Mọi socket là `!Send + !Sync` (`PhantomData<*const ()>`), nên
   không gửi được sang worker khác. Ở epoll đây là điều kiện để chạy đúng, không chỉ để nhanh,
   vì bảng fd và `em_close` là của từng worker. Fiber con không cần `Send` vì nó không bao giờ
   rời worker.
2. **Gọi ngoài fiber.** Thread worker 0 cũng là thread gọi `em_run`. Một socket bị
   `Box::leak` rồi cất vào `thread_local` có thể bị dùng sau khi `run` đã trả về, lúc `em_W`
   không còn ring nữa, và đó là UB. Sửa ở phía C: mọi lệnh công khai gọi khi
   `em_W.current == NULL` thì trả `-EPERM`; riêng `em_close` khi đó chỉ `close()`. Chỉ thêm
   một nhánh trên TLS mà hàm vốn đã đọc. Người dùng C cũng được lợi. Đây là thay đổi API C
   duy nhất, và chỉ là thêm một mã lỗi.
3. **Lỗi của fiber con.** Con trả `Err(e)`. Binding giữ lỗi **đầu tiên** của scope (dạng
   `io::Error` nguyên vẹn, không ép về errno), báo C một mã khác 0 để anh em bị hủy, rồi
   `scope` trả đúng lỗi đó. Lỗi không phải lỗi OS, kiểu `io::Error::other("bad frame")`,
   cũng không mất thông tin.
4. **Panic.** Trampoline của fiber là `extern "C"`, bọc `catch_unwind`. Panic thì làm như
   lỗi ở mục 3: payload được giữ trong scope, anh em bị hủy, và `scope` ném lại sau khi đã
   đóng. Thân hàm `scope` cũng nằm trong `catch_unwind`: panic ở thân thì vẫn hủy và **đợi
   hết con** rồi mới ném lại. Nếu không đợi, các fiber con sẽ trỏ vào stack đã bị giải phóng.
   Cách này giống `std::thread::scope`.
5. **Backtrace trên stack fiber.** `RUST_BACKTRACE=1` sẽ đi lên tới `em_tramp`. Đã có test
   kiểm chuyện này. Nếu unwinder không dừng được ở đó thì thêm `.cfi_undefined` cho return
   address vào `em_tramp` (x86_64 và aarch64).
6. **Hủy và timeout** trả `io::Error::from_raw_os_error`: `ECANCELED`, còn `ETIMEDOUT` thì
   thành `ErrorKind::TimedOut`. Không bao giờ ra `EINTR`, nên `read_exact`/`write_all` không
   tự lặp lại sau khi bị hủy. `Drop` chạy bình thường khi fiber unwind vì bị hủy hay vì deadlock.
7. **`em_scope` trên stack Rust.** Struct được mô phỏng lại bằng `#[repr(C)]`. `build.rs`
   biên dịch một file C có `_Static_assert` kích thước/căn lề khớp với hằng số mà Rust cũng
   `const`-assert. Struct không bao giờ bị move: nó nằm trong frame của `scope()`, và chỉ
   phát ra `&Scope`.

## Build

- Thư mục `rust/em/`: một crate. `build.rs` dùng `cc` biên dịch `src/*.c` cùng asm theo
  `target_arch`, rồi link `uring`. Khai báo FFI viết tay trong `src/ffi.rs` (khoảng 25 hàm),
  không dùng bindgen.
- `bench/rust/` thêm `em_rs_echo` (dependency kiểu path). `run.sh` thêm hai server
  `emrs-uring` và `emrs-epoll`.
- `make test-rust`: chạy `cargo test` hai lần, `EM_BACKEND=uring` và `EM_BACKEND=epoll`, với
  `--test-threads=1` vì mỗi test là một `em_run`. CI chạy target này trên x86_64 và arm64.

## Test — xong M4 khi xanh trên CI

1. **Echo bằng code sync có sẵn:** server đọc theo dòng bằng `BufReader<&TcpStream>::read_line`,
   client dùng `TcpStream`. Chứng minh code `impl Read` chạy được nguyên trạng.
2. **Mượn biến:** các fiber con ghi vào một `RefCell<Vec<_>>` cục bộ của hàm cha. Sau `scope`
   có đủ phần tử.
3. **Timeout:** `scope_timeout(10ms)` quanh `read` trên connection nhàn rỗi. Kết quả là
   `ErrorKind::TimedOut`, và `Drop` của guard trong fiber đã chạy.
4. **Lỗi lan:** fiber A trả `io::Error::other("x")`, fiber B đang chặn ở `read` bị hủy. `scope`
   trả đúng lỗi `"x"`.
5. **Panic:** con panic thì anh em bị hủy, `run` ném lại đúng payload đó. Chạy thêm một lần với
   `RUST_BACKTRACE=1`: tiến trình không chết vì unwinder.
6. **Ngoài fiber:** `em::sleep` gọi ngoài `run` trả `Err` (`EPERM`). `run` lồng trong `run` trả
   `EBUSY`. Thêm một test C cho phần guard (t30).
7. **UDP:** `send_to`/`recv_from` qua lại.
8. **`!Send`:** doctest `compile_fail` gửi `TcpStream` sang `std::thread::spawn`.
9. **Bench:** `emrs-*` nằm trong nhiễu so với `em-*` C cùng backend (trung vị, chênh ≤ 5%,
   trong cùng một job). Đây là thước đo cho "binding mỏng".

## KHÔNG làm

- Không async/`Future`, không tích hợp tokio. em là sync có chủ đích (D1).
- Không channel, mutex hay `park/unpark` cho Rust. Trạng thái chung trong một worker thì
  dùng `Cell`/`RefCell` là đủ. Thêm khi có người dùng thật cần đợi giữa các fiber.
- Không `FromRawFd`/`IntoRawFd`: fd tạo ngoài em có hợp đồng `em_close` riêng (xem `em.h`).
  Thêm khi cần, kèm hợp đồng đó.
- Không `ToSocketAddrs` hay DNS (v0.1, D6).
- Không publish lên crates.io, không vendor mã C vào crate. Làm khi có người dùng ngoài repo.
- Không bindgen, không tách crate `em-sys`. Chỉ có một người dùng là crate `em`.
- Không chạy ASan cho Rust (cần nightly). Phần C đã có ASan; phần Rust an toàn nhờ kiểu.
- Không bọc stack overflow: tràn stack 256 KiB vẫn là SIGSEGV ở guard page (D7), ghi vào tài liệu.

## Trade-off

- **Mỗi `spawn` cấp phát một `Box` cho closure.** Quy tắc 3 không cho cấp phát khi spawn,
  nhưng muốn bỏ thì phải thêm API C chép closure vào stack fiber. Xét lại khi bench churn
  connection ở M5 cho thấy `malloc` nằm trong profile.
- **Bản ghi lỗi/panic theo scope** là một `Cell<Option<..>>` trên stack của `scope()`. Chỉ
  giữ lỗi đầu tiên, các lỗi sau bị bỏ, giống ngữ nghĩa C.
- **`run` trả lỗi của một worker:** lỗi Rust giữ dưới `Mutex`, ai khóa trước thì thắng. Đây
  là xấp xỉ của "lỗi đầu tiên theo thời gian" bên C. Mutex chỉ bị chạm một lần lúc kết thúc,
  không nằm trên đường nóng.
- **Thread-local của Rust là chung cho mọi fiber trên một worker.** Ghi vào tài liệu.
- **Gọi thư viện chặn** (`std::fs`, `std::net`, `thread::sleep`) sẽ đứng cả worker (D6). Ghi
  vào tài liệu crate ngay ở đầu.
